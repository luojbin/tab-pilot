分组色 · 感知色度图 CIE 1976 Lab · a*b* 平面

把 9 个分组色放到感知均匀的色彩空间里，点与点的直线距离就约等于人眼看到的差异。红线连起来的，是 ΔE00 < 20（肉眼容易混淆）的配色对。可切换 Edge / Chrome / Firefox / TabPilot 现实现 / 建议色板，共 11 套数据。

为什么是这张图，而不是常见的色环或马蹄形色度图？

✗ HSV 色环 / CIE 1931 xy 马蹄图

都不是感知均匀的：图上离得远，看起来未必差得多。直接拿来量"区分度"会误导判断。xy 图还把明度完全丢掉了。

✓ CIE Lab 的 a*–b* 平面

感知均匀空间的截面，两点直线距离≈感知色差，与我们一直用的 ΔE00 同源。横轴 a* 绿→红，纵轴 b* 蓝→黄，越靠外越鲜艳。

注意：a*b* 平面是二维截面，不含明度 L*。所以右侧另配了一条 L* 明度标尺——这一维恰好是 Edge 浅色的问题所在：9 色里有 7 个挤在 L* 43–50，明度几乎没参与区分，全靠色相和彩度硬撑。

图上还标了浅色背景 #FFFFFF 与深色背景 #202124 两个锚点。它们在 a*b* 平面上几乎重合（白底 a\*0/b\*0，深底 a\*0.3/b\*−2.2），因为都是中性色、只差明度（L\* 100 vs 12.7）——所以平面距离不代表边框在页面上的可见性。可见性要看下方新增的 WCAG 对比度面板。

a*–b* 色度平面

全彩底图是 sRGB 所有明度层并集——每个 (a*,b*) 位置取一个能落入色域的 L* 用真实色渲染，因此覆盖全部色点（单个 L* 的截面会漏掉高彩度色）。它只作色相参照、不随数据集变化；越靠外越鲜艳。圆点填充为真实色值，红色连线标出 ΔE00<20 的混淆对；关掉底图时显示 sRGB 全明度包络线。叠加后紫色虚线箭头上的数字是 a*b* 平面位移量（非 ΔE00）。

    背景可见性 · WCAG 对比度

    每行是一条连续长条、无缝三段：左纯白底、中目标色块铺底（同时叠白字和黑字看哪种更清楚）、右纯深底。左右不放小色块，直接看白底/深底与中段目标色块的交界就能判断区分度，旁边给出对应分值。≥3.0 才看得清图形轮廓（WCAG AA 图形元素标准），低于 3.0 标红。左段分值 = 白字压在色块上的对比度（白 vs 色，对称），分值低则白字发虚、宜改用黑字。

    各色板最小 ΔE00 / 混淆对（<20）数量： Edge Win 浅 10.3 / 4、Edge Win 深 10.6 / 5、Edge mac 浅 10.2 / 4、Edge mac 深 9.9 / 7； Chrome 浅 14.6 / 2、Chrome 深 13.9 / 5； Firefox 浅 10.3 / 3、Firefox 深 11.9 / 5； TabPilot 现实现 19.2 / 1；建议色板 浅 22.8 / 0、深 21.2 / 0。
    读图要点：Edge 的紫区（粉红/紫罗兰/紫）与蓝区（亮蓝/蓝）各贴成一簇；Chrome 浅色靠拉大明度差缓解，但深色同样挤；Firefox 浅色仍糊在紫区。 TabPilot 现实现因为取的是旧版 Chrome 浅色、明度分布较散，反而是混淆对最少的一套（只 1 对），代价是与三家原生色都对不上。 叠加"建议色板 · 浅"可以看到紫色虚线箭头把每个点推离原生位置，混淆对从 4 对降到 0 对。
    坐标由 sRGB 经标准 Lab 转换计算；ΔE00 采用 CIEDE2000；全彩底图逐像素搜索能落入 sRGB 色域的明度层并取真实色，覆盖全部 11 套共 99 个色点（只作色相参照），关底图时显示的包络线由 sRGB 立方体全明度采样取得。页面纯静态，可直接保存分享。
