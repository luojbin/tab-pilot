建议色板怎么来的：色相基本不动，只重排明度。除后面单独说明的三处例外，其余各格固定 Edge 原生色相（允许 ±5° 偏移），彩度不低于原生的 86%（深 blue 是唯一例外，只有 67%），把明度按三档重新分配；目标是每格与原生 ΔE00 ≤ 13（「还是那个颜色」）、在底色上对比度 ≥ 3.1（边框不被页面吃掉），未达标或主动偏离的几处原因见下（真正 ΔE00 越界的只有 pink）。结果：浅色最小 ΔE00 由 10.3 提到 22.8，36 对里低于 20 的从 4 对降到 0 对；深色最小由约 10 提到 21.2，低于 20 的同样是 0 对。
为什么要重排：Edge 把 9 个色的明度压进 L* 43–50 这条窄带里，人眼只剩色相可用，而紫/紫罗兰/粉三色又只差 20°。拉开明度是唯一不动色相又能分开的办法。
一个刻意的例外：pink 不再跟随原生色相，改成警示红。Edge 的粉红 #E3008C 是全 9 色里最接近正红的一个（色相 352°，其余八个都在 200–340° 或黄区），所以把这一格从 352° 推到 18°、彩度提到接近上限，得到 #E3004E（深色 #FF7B85）——整组里唯一一个「一眼就是红色」的槽位，用来标示需要立刻注意的规则。色相只移了 34°，仍带玫红底子，不会跳到纯橙红去和 orange（色相 53°）撞车：两者 ΔE00 为 27.0，整表最小 ΔE00 是 green/grey 与 green/blue 并列的 22.8，低于 20 的对数还是 0。代价有三条：该槽位与原生分组色差 15，不再算「近似」；配置页里这一项在 Edge 上叫「粉红色」，色块却是正红，需要在文案上标注；其余各格通常控制在 ±5° 内；cyan 和深色 green 的主动偏离见后文。
cyan 则既换方向也提了彩度：色相从 203° 移到 180°，彩度从 30 提到 40——这是 sRGB 在这个明度与色相下能给出的上限，再高就溢出色域。得到浅 #00A08D / 深 #45C8B5，明度不动，仍与相邻色处于同一明度档，只是从「灰蓝绿」变成一块干净的青绿。收益是与 blue、green 这一簇的间距从 29.7 拉到 37.4，同表里不再有两块「都像蓝」的色。代价是与 Edge 原生青色的 ΔE00 从 9.1 涨到 13.0（深色 9.5），刚好贴着「≤13」这条线——所以它也从「轻微近似」变成了「主动偏离」，幅度比 pink 和 yellow 都小。
yellow 提亮后为避免描边又收了一档：原来的浅色 #805F0A 是照搬原生明度的结果（L* 42），看上去像橄榄；先拉到 L* 70 得到 #D4A428，但它在白底对比度只有 2.30、必须配描边才不发飘。于是收回到 L* 58、彩度 64，得到现在的 #B08500（深色仍是 #F3C663）：白底对比度升到 3.39，与其余各格一样达标，不再需要描边。调整后与 Edge 原生黄的 ΔE00 8.7，仍属于本项目的近似目标范围——想亮又想达标，只能从原生深金走到这个深琥珀。
orange 往黄挪了 6°、把彩度推到色域上限，明度为达标而下调：现在浅色是 #E66415（L* 58 / C* 78 / h 53°），深色是 #FC863D（原生 C* 58 先提到 78 拉开距离，后来觉得在一片灰白里过于扎眼，又收回 70、色相从 58° 微拨到 55°）。起因是它与 pink 的警示红贴得太近：色差 27.0 看着不算小，但两者彩度接近，唯一的分隔是色相，而 47°→18° 恰好落在红橙边界上，是人眼最钝的一段。橙色又正好被 pink（18°）和 yellow（84°）夹在中间——往黄推会撞黄，往下沉会变成焦糖（已否决「太暗」的观感），只剩往黄挪 + 提彩度这一条路：原生的 C* 72.5 在 L* 58 / h 53 处还能往上推。结果红橙 ΔE00 拉开到 27.0，橙黄 23.5，两头都守在 23 以上。最初提亮到 #F36F22 时白底对比度只有 2.95，与黄色一样要靠描边；这次连黄色一起把明度压到 L* 58，白底对比度升到 3.39，描边需求一并消除。深色侧收彩度、色相微拨后：红橙 22.5、橙黄 23.2，两头仍守在 22 以上，深色表低于 20 的对数保持 0（此前还把 green 色相从 256° 微调到 236°，消除了它与 purple/blue 的混淆对）。
顺带说明 red 为什么偏浅：建议版里 red（紫罗兰色）比 pink 更浅——不过现在已经不是「被 pink 逼出来的」，而是它与 purple 只差 20°，两者必须靠明度错开，否则紫区又会糊成一片。若坚持「紫罗兰应该更深」，只能把 red 整体换到红区（如 Fluent 的 #D13438），代价是与 Edge 分组标签彻底不同色相，且会与 orange 撞。
两点边界：色板只优化正常色觉——模拟三类常见色觉障碍后，深色 protan 的 pink/grey ΔE00 只有 2.4、deutan 的 red/blue 2.0、tritan 的 pink/orange 5.8，所以「ΔE00 全部 > 20」不等于所有用户都能分清，组名前缀是必需的第二维度。另外色相归属是按 Edge 定的：这套表拿到 Chrome 上时 green 与原生差 49.0、red 差 32.2、pink 差 22.0——因为 Edge 的 red 本就是紫罗兰、green 本就是亮蓝，别把它当成「更准」的 Chrome 色板。
第 2 列由 API 枚举名直接作 CSS 颜色渲染，代表「按名字本该是什么色」，与任何浏览器的实际渲染都不同。
第 3 列取 src/app/store.js 的 GROUP_COLOR_HEX，现作为“经典”主题保留；页内边框与 banner 的实际颜色由全局色彩主题决定。
Chrome 列与 tab_group_color_ids.h 的 *LightMode / *DarkMode 常量完全一致，可作取色基准；Edge、Firefox 为截图实测（2026-11-26，Windows 11 与 macOS）。Edge 两列同枚举的浅色平均 ΔE00 2.5、深色 2.3，属同一套色板，分开列只为看采样误差（Windows 开了 Mica，底色会透一点窗口背景）。
