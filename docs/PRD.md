## 1. 背景与问题

当前通过多个独立浏览器插件分别实现“标签页分组、高亮、重命名”等能力，存在：

1. **零碎**：规则散落在多个插件，行为不一致，难以统一调整。
2. **不可控**：无法集中定义“什么 URL 进什么组、什么颜色”。
3. **不可迁移**：配置无法备份/恢复，换机器成本高。
4. **权限冗余**：多个插件叠加申请权限，隐私面扩大。

目标：用一个自制浏览器扩展，以**统一规则引擎**收编 80% 高频场景，其余低频操作保留手动。

## 2. 目标与非目标

### 2.1 目标（v1.0.0 验收）

- 用 JSON 规则定义“URL 匹配 → 分组/颜色/折叠”。
- 规则可启用/禁用、可按顺序决定优先级、支持导入导出。
- 能在控制台排查“哪个 tab 命中哪条规则、做了什么”（不单独做日志页，见 F5）。
- 连续使用一周，可卸载至少一个现有旧插件。

### 2.2 非目标（本阶段明确不做）

- Safari 兼容（Chrome / Edge 已纳入 v1.1 规划，见 §13）。
- 更复杂的规则编辑器（条件组合、表达式、自由画布；当前两栏表单已够用）。
- 云同步、账号体系。
- 标签页名规则已实现（F6）；更复杂的标题模板语法（条件、函数、多规则串联）不做。
- 机器学习/智能推荐规则。
- 按域名细分统计标签数（阈值按规则整体计数，已决策）。
- **按容器（Container Tabs）/ 窗口区分规则**：容器的主要价值是隔离登录态与 Cookie，属于“同一环境多账号”的少见场景；真需要时用不同浏览器或隐私窗口即可，不纳入插件目标。窗口维度也不需要——分组本身已按窗口隔离，同一窗口内不需要多套规则。
- 任何形式的数据上传。

## 3. 用户与场景

**目标用户**：需要频繁在多环境之间切换的开发者，日常使用 Firefox / Chrome / Edge。

核心场景：

| #    | 场景                        | 期望行为                   |
| ---- | --------------------------- | -------------------------- |
| S1   | 打开 `localhost:*` 调试服务 | 自动进入“开发”组，绿色     |
| S2   | 打开 GitHub / GitLab        | 自动进入“代码”组，蓝色     |
| S3   | 打开 Jira / Confluence      | 自动进入“工作”组，橙色     |
| S4   | 同一分组规则命中的标签过多   | 可选：同一窗口内命中该规则的标签数达到规则阈值（`minTabs`）时自动归组；按规则整体计数，不按域名细分 |
| S5   | 临时不想被自动分组          | 可禁用单条规则   |
| S6   | 换机器                      | 导出 JSON 配置，新机器导入 |

## 4. 功能需求

### F1 规则引擎自动分组（P0，核心）

- 新建标签页、页面加载完成或 URL 变化后，自动按规则处理。
- 按规则在配置中的顺序（即优先级）匹配 URL；命中后执行动作。
- 阈值：每条规则可自定义 `tabGroup.minTabs`（默认 `1`，即命中即归组）。设为 N 时，只有同一窗口内首条命中归属该规则的标签页数量 ≥ N 才归组；未达阈值时保留首条命中的规则归属，仅不执行浏览器分组。页面标识和重命名不受该阈值限制。计数按规则整体统计，不做域名细分（已决策）。达成阈值时，同窗口内命中该规则且尚未归入任何分组的标签页一并归组，已在其他分组内的标签保持不动。
- 幂等：已处于目标组/颜色则不重复操作。
- 全量同步：事件监听覆盖不到已打开的标签页，因此提供「同步」动作——保存配置后自动执行，也可由工具栏按钮或控制台手动触发。默认跳过已在分组内的标签，避免覆盖手动整理结果。
- 防循环：分组动作不会触发反复处理。
- 批量/防抖：短时间多个 tab 事件合并处理。

**验收**：打开 3 个 `localhost` 页面，自动进入同一“开发”组、绿色，日志各打印一条命中记录。

### F2 分组属性设置（P0）

- 支持设置分组：名称、颜色（Firefox 预设色）、是否自动折叠。
- 折叠在 Firefox 上按原生行为处理；跨浏览器折叠差异不在本版范围。
- 自动折叠以实际入组为触发条件：创建新组，或组外标签成功移入目标组后，collapsed=true 才执行折叠。活动/后台标签已在组内时，导航、刷新或重复规则命中不改变折叠状态，颜色等属性照常更新；collapsed=false 不主动展开已有组。
- 普通同步也仅在实际入组时应用自动折叠。显式的按规则折叠、折叠非活动分组、折叠所有分组动作保留。阈值带入新成员视为实际入组，动作层重新查询成员避免旧快照重复处理；入组失败不折叠目标组。

**验收**：规则中改颜色后，新命中 tab 使用新颜色；已有组按规则更新。

### F3 规则管理（P1）

- 规则字段：`id`、`enabled`、`name`、`color`、`collapsed`、`minTabs`、`note`、`patterns[]`。
- 支持启用/禁用单条规则；扩展内全局启停开关在 v1.3.0 移除。
- 冲突处理：规则按数组顺序匹配，靠前的优先；默认一个 tab 只应用一个分组规则。
- 阈值按规则独立配置，不同规则组互不影响。
- 新建分组按序号在 9 个预设色里循环取色，相邻分组默认不同色，减少手动改色的次数。
- 配置界面为两栏布局：左栏分组列表支持选中、拖拽排序（色块、名称、只读拨杆表示启用状态、⋯ 菜单内复制/排序/删除；新增菜单可从当前窗口生成规则），左栏不提供编辑入口。右栏分成三个可独立折叠的区块（记住折叠状态，默认只展开基础配置；折叠时标题栏右侧展示突出显示和标题规则的启停状态）：**基础配置**（分组名/颜色/阈值/启用/自动折叠、严格模式、备注、匹配路径）、**页面内突出显示**（开关、示意预览、边框与 banner 配置）、**标签页名规则**（开关、命名规则列表、标题/URL 测试用例）。不使用裸 JSON 编辑（JSON 导入导出属 F4）。
- 匹配路径自动补全：输入简写即可，离开输入框或保存时展开为完整模式——不带协议补 `*://`；只写主机且无路径时同时生成「任意端口」与「无端口」两条（如 `192.168.3.213` → `*://192.168.3.213:*/*`、`*://192.168.3.213/*`）；已写端口则不展开端口变体；结尾自动补 `/*`。

**验收**：禁用某规则后，新 tab 不再命中；重新启用恢复。

### F4 配置导入/导出（P1）

- 导出为 JSON 文件（含 `schemaVersion`），文件名带日期；入口在左栏「全局配置」→「配置管理」。
- 导出内容为**已保存**的配置。页面存在未保存修改时禁止导出，并提示先保存或放弃修改，避免导出内容与生效配置不一致。
- 替换导入时校验 schema 版本与字段合法性，非法则拒绝并逐条提示，不改动现有配置；正式 schema 1 直接迁移为 2，其余版本或非法结构拒绝。
- 导入确认后替换当前配置，立即保存并同步已打开的标签页。
- 支持“恢复默认”。
- v1.3.0 新增「追加导入」，仅取文件中的分组规则、忽略全局设置并处理名称/id 冲突，具体见 §14.4。

**验收**：导出 → 清空 → 导入，规则与行为完全恢复。

### F5 操作日志（开发期辅助，不做独立页面）

- 记录：时间、tab URL、命中规则 id、执行动作、结果/错误。
- 结论：日志的主要使用者是开发者本人，交付给用户价值很低。因此**不做独立日志页**，保持控制台输出即可。
- 提供未命中路径、阈值不足和动作失败等诊断信息，便于排查没有归组的原因。
- 日志仅本地、不上传；内存环形缓冲保留供调试。

### F6 标签页名规则（P2，实验 → v0.5.0 已实现）

- 通过 content script 修改 `document.title` 实现；只要标题规则开着就持续监听：**初始标题不匹配也不会放弃**，等页面把标题改成最终值后再应用；之后每次改名（含单页应用路由切换）都会重新按顺序匹配。页面反复修改标题时也应重新应用规则。
- 每个分组配置 `titleRule = { enabled, rules: [{ titlePattern, urlPattern, replacement, description }], testCases: [{ title, url }] }`。
- 两个正则条件至少填写一个；留空表示不限制，同时填写时须同时命中。不支持标志位。按规则顺序取首条命中；标题条件隐含 `^(?:pattern)$`，URL 条件也隐含 `^(?:pattern)$`，如需允许后续路径、参数等变体须显式添加 .*。显式首尾 ^ / $ 与默认边界等价，转义的美元符号不移除；非捕获包装不改变捕获组编号。replacement 始终生成完整的新标题。
- 模板用 `${title.1}` / `${url.1}` 引用捕获组，`${title.name}` / `${url.name}` 引用命名组，`.0` 表示完整匹配，`$$` 输出美元符号。缺失捕获组为空串，捕获内容不再次解释。旧 `$1` / `$<name>` / `$&` 只在 schema 1 迁移时转换为新版带来源语法，运行期不解释旧语法。
- 配置页在标题条件两侧固定显示 ^ / $，URL 条件两侧显示 ^ / $，占位符提示匹配路径和参数等变体需显式添加 .*，符号不可编辑、不写入字段；输入框失焦去除冗余边界，保留转义美元及仅含边界条件的含义，留空表示不限制。提供双条件输入和结构化测试行，每行分别填写标题和 URL，支持添加、删除、预览；测试用例随配置保存、导入导出。关闭标题规则时配置区禁用。保存前校验两种正则及测试数据类型，运行时跳过非法规则。
- 标题或 URL 变化时使用原标题及当前 URL 重新计算，覆盖固定标题的 SPA 路由切换；扩展自身写标题不循环套用。URL 不再命中时恢复原标题。与页面内标识独立生效。

**验收**：标题 `App`、URL `https://example.com/projects/demo`，URL 条件 `https://example\.com/projects/([^/?#]+)`、目标文本 `${url.1} · ${title.0}`，结果 `demo · App`；仅 URL 改为 `/projects/test` 后结果 `test · App`；测试用例保存后可复用。正式 schema 1 的标题字段和测试文本自动迁移；旧捕获引用自动转换为新版带来源模板，片段匹配条件需要改写为完整标题正则。

### F7 页面内标识（P1）

- 每个分组独立的开关：开启后，命中该分组的页面里显示标识；关闭或未命中则不注入任何元素。默认配置为**四边边框 + 左上角 banner**（开关默认关闭）。
- 边框：可勾选上 / 下 / 左 / 右，宽度可调（1–24px），颜色取该分组的颜色。
- 不透明度：边框与 banner **分别控制**（0–100）。边框默认 100（不透明），banner 默认 60，便于既醒目又不完全遮挡内容。
- 配置页提供 16:9 的示意预览：用细条/斜线标出边框与 banner 的目标区域，颜色与透明度跟随配置，banner 内以 `XXX` 占位；不按真实尺寸渲染、不显示真实分组名，仅用于快速确认位置。
- Banner：可选上 / 下 / 左 / 右与四个角；上下为贴着上/下边缘的小横标签、左右为贴着左/右边缘的小竖标签，长度随文字收缩（只比文字略宽），靠页内一侧做圆角。四个角为 45° 斜带，横跨角部，**两端越过页面边缘并被裁掉**（不会露出方角）。文案为分组名，尺寸（8–160px）与字号（8–32px）可调。
- 覆盖层 `position: fixed`、`pointer-events: none`，不拦截页面交互；配置保存后已打开的页面立即重绘。
- 支持可注入的 http(s) 页面，使用当前网址匹配规则；不采集页面正文、不发起网络请求。

**验收**：给「开发」分组开启上下边框 + 右上角斜向 banner，打开 `localhost` 页面即可看到；修改颜色/宽度/字号并保存后，页面无需刷新即更新。

## 5. 数据模型

当前新增 `tabGroup` 对象统一管理 enabled / minTabs / collapsed / strictMode。规则总开关保持独立；首条 URL 命中后即确定规则归属，不因群组关闭或阈值不足继续匹配后续规则。阈值和批量归组只计算同窗口归属本规则的标签；页面标识和重命名不受群组开关、阈值影响。关闭群组不会主动删除已有原生组。旧 schema 1 的规则级群组字段迁移至 tabGroup，新增群组开关默认 true。

各格式版本的字段、默认值、JSON 示例和迁移约定见 [配置 JSON 格式参考](schema-reference.md)。

`schemaVersion: 2`（1.3.0 群组配置独立，直接迁移正式 schema 1）。一条规则对应一个标签页分组，`patterns` 可包含多个匹配路径，数组顺序即优先级，`highlight` 描述页面内标识，`titleRule` 描述标签页名规则。

```json
{
  "schemaVersion": 2,
  "language": "auto",
  "clickAction": "sync",
  "autoUpdateGroupRules": true,
  "showActionResult": true,
  "groupsFirst": false,
  "rules": [
    {
      "id": "dev-localhost",
      "enabled": true,
      "name": "开发",
      "color": "green",
      "tabGroup": { "enabled": true, "minTabs": 1, "collapsed": false, "strictMode": false },
      "note": "本地开发环境",
      "patterns": ["*://localhost:*/*"],
      "highlight": {
        "enabled": true,
        "border": { "sides": ["top", "bottom"], "width": 6, "opacity": 100 },
        "banner": { "positions": ["topRight"], "size": 34, "fontSize": 15, "opacity": 60 }
      },
      "titleRule": {
        "enabled": true,
        "rules": [
          {
            "titlePattern": "^\\[工作\\]\\s*(.*)$",
            "urlPattern": "",
            "replacement": "W· ${title.1}",
            "description": "Jira / 工作"
          },
          {
            "titlePattern": "^(.*) - (.*)$",
            "urlPattern": "",
            "replacement": "${title.2} · ${title.1}",
            "description": "通用重排"
          }
        ],
        "testCases": [{ "title": "[工作] Jira - 看板", "url": "https://github.com/team/repo" }, { "title": "Jira - GitHub", "url": "https://github.com/" }]
      }
    }
  ]
}
```

- 配置在本机保存；日志只在内存与控制台，不落盘。
- **分组阈值 `minTabs`**：整数，默认 `1`。值 N 表示同一窗口内命中该规则的标签页数量达到 N 时才执行归组（多域名合并的规则一起计数，不按域名细分）。该字段属于规则自身，不同规则组各自定义、互不影响。
- **优先级**：不再用显式字段，规则在 `rules` 数组中的顺序就是匹配顺序，靠前的优先；配置页可拖拽或用上移/下移调整。
- **旧全局开关移除**：v1.3.0 起不再提供 globalEnabled 开关或暂停判断。读取和导入旧配置时忽略并移除该字段，保存和导出也不再写入；兼容迁移正式 schemaVersion 1。规则自身的 enabled 保留。
- **点击插件图标 `clickAction`**：全局字段，取值 `sync`（仅同步，默认）、`syncRuleCollapse`（同步后按规则里的「自动折叠」折叠）、`syncCollapseInactive`（同步后折叠不含活动标签的分组）、`syncCollapseAll`（同步后折叠所有分组）。同步覆盖所有窗口；折叠只处理点击时所在的窗口。未知值在读取时回退到 `sync`。
- **分组前置 `groupsFirst`**：可选布尔值，默认 false；全量同步完成后在各窗口内整组前移；自动新建/归组、阈值批量归组、手动归属变化和严格模式移出后，也会合并事件并整理受影响窗口。保持分组在前、游离标签在后，无需重复移动已到位的组。
- **自动更新分组规则 `autoUpdateGroupRules`**：可选布尔值，默认 true；控制手动拖入已有规则对应分组时是否询问追加匹配路径。关闭后停止新提示，清除待确认项与角标，未完成的旧表单不能再写入规则；不进行无确认的自动更新。
- **自动折叠 `rules[].tabGroup.collapsed`**：沿用原布尔字段，不改变配置键名；仅实际创建组或成功入组时按 true 折叠，组内导航不改变状态，false 不主动展开。
- **组内严格模式 `rules[].tabGroup.strictMode`**：规则上的可选布尔值，默认 false；仅开启该字段的组参与严格判断；导航处理时，若标签当前组能唯一对应一条已启用规则，而导航目标 HTTP/HTTPS 地址不匹配其 patterns，则调用 tabs.ungroup 移出。匹配涵盖协议、主机、端口和路径，不受 minTabs 阈值影响；固定标签、无对应规则、重名歧义及浏览器内部/临时空白页不处理。处理前重新读取实际标签状态，归属已变则跳过。移出后本批不立即重新归组；手动拖入本身不触发严格检查，后续导航才检查。手动同步不主动清理既有分组。
- **严格模式兼容**：旧全局 strictMode 为布尔值时，迁移至缺省该字段的规则；组内显式值优先。保存/导出移除全局 strictMode，保留规则字段。追加导入忽略所有全局字段，不用旧全局值覆盖导入规则。
- **操作结果提示 `showActionResult`**：可选布尔值，默认 true；控制插件图标快捷动作完成后的结果展示。关闭后仍执行动作，完成即关闭 popup，不显示结果或启动 3 秒倒计时；不影响手动添加匹配路径的确认表单和保存反馈。
- 全局配置中的语言、图标行为和三个功能开关统一为两列等尺寸卡片；功能开关使用已有拨杆样式，随保存、导入导出与恢复默认生效。旧配置缺省按默认值处理，非法字段类型拒绝保存或导入。
- **界面语言 `language`**：全局字段，取值 `auto`（跟随浏览器，默认）、`zh`、`en`。属于配置本身，随保存、导入 / 导出一起迁移；未知值回退到 `auto`。
- **分组名唯一**：同一份配置里不允许两个分组同名——浏览器原生分组按标题复用，同名会让两条规则落进同一个分组，颜色 / 折叠互相覆盖。保存与导入时校验并拒绝，错误信息带两个分组的序号，配置页同时高亮；读取历史配置时放宽该校验（`allowDuplicateNames`），避免整份配置因为重名回退到默认值。
- **匹配路径**：`patterns` 数组，任一命中即视为该规则的 URL 命中。
- **页面内标识 `highlight`**：`enabled` 开关；`border.sides` ⊂ top/right/bottom/left，`border.width` 1–24；`banner.positions` ⊂ top/right/bottom/left/topLeft/topRight/bottomRight/bottomLeft，`border.opacity` 0–100（默认 100）、`banner.size` 8–160、`banner.fontSize` 8–32、`banner.opacity` 0–100（默认 60）。保存和导入时拒绝越界数值；渲染时对缺省字段使用默认值并进行边界处理。不支持旧的统一 `highlight.opacity` 字段，需分别配置边框和 banner 透明度。
- **标签页名规则 `titleRule`**：结构和匹配/替换语义见 F6。正式 schema 1 的 `pattern` 迁移到 `titlePattern`，`urlPattern` 为空；将旧捕获引用转换为新版带来源模板，新版统一按完整标题匹配；旧片段条件需显式补充 .*；旧文本中的非空行迁移为 `{title, url: ""}`。迁移不修改输入；读取后保留旧存储，下一次保存写 schema 2。schema 2 拒绝旧 `pattern` / `testText` 字段。
- **基线说明**：1.0 正式配置从 1 起算，1.3.0 当前统一为 2；早期开发期格式无迁移支持，即使编号相同也须通过当前结构校验。未知版本直接拒绝。新版导出不可直接导入旧版插件，升级前保留旧备份。
- `schemaVersion` 与插件版本号解耦，仅随配置结构的不兼容变更递增。

## 6. 非功能需求

| 碎片时间导致中断                         | 在任务记录或 Issue 中记录下一步，便于恢复工作                  |

**开放问题**：

1. ~~是否需要“同域名超过 N 个自动归组”？~~ 已决策：需要阈值机制，但**不做域名细分**——阈值按「同一窗口内命中该规则的标签数」整体统计（`minTabs`，默认 1），见 §5。
2. ~~日志用 `storage.local` 还是 IndexedDB？~~ 已决策：不做日志页，日志只在控制台与内存，用于开发期排查。

## 13. 多浏览器支持与验收

### 13.1 目标与范围

- 支持 Firefox 140+、Chrome / Edge（Chromium 116+）桌面版本，Safari 与 Android 不在当前范围内。
- 在三个浏览器上提供相同的规则、配置导入导出、自动分组、页面标识与标题改写能力。
- 保持现有功能与配置格式；允许原生分组外观和折叠细节存在浏览器差异。

### 13.2 验收标准

1. 同一份导出 JSON 在 Firefox / Chrome / Edge 导入后，规则、颜色和阈值行为一致。
2. 新建、导航和保存配置后能按规则处理标签，且同窗口阈值、优先级、已分组标签保护符合 F1。
3. 页面边框、banner 和标题规则在 Chromium 上可用，覆盖刷新、SPA 标题变化和停用后的恢复。
4. 配置页的编辑、预览、保存及 JSON 导入导出正常；重启浏览器后配置保留（正式安装）。
5. 对应浏览器的商店校验和签名要求满足；插件版本、仓库 tag 与商店版本一致。

### 13.3 当前验证状态

- Firefox：已有功能有历史实机验证记录；当前构建的静态校验无错误，有一条 Android 兼容警告。
- 权限：Firefox 中 host 权限在扩展内申请 / 撤销与 `about:addons` 的权限开关双向同步（已实机验证）；Chromium 将同一权限视为必需权限，扩展内不提供控件，需在扩展详情页的「站点访问权限」里调整。
- 自动化：当前完整测试 246 项通过，包含模块单测和两种浏览器 API 命名空间下的打包冒烟测试。
- 当前发布基线：已确认 v1.2.0 发布上线，相关功能已在 Firefox / Chrome / Edge 三浏览器实测通过。
- 发布渠道（登记日期：2026-11-21）：[Firefox AMO](https://addons.mozilla.org/zh-CN/firefox/addon/tabpilot-firefox/) 的 1.2.0 已上架；[Edge Add-ons](https://microsoftedge.microsoft.com/addons/detail/tabpilot/cdjpnbjccmeddhagmbbgjcckjfnofbbn) 的 1.2.0 已上架。1.3.0 暂无商店发布记录。
- 构建、兼容实现、开发检查清单和发布步骤统一维护在 [开发指南](../CONTRIBUTING.md)。

### 13.4 风险与限制

- 原生分组及折叠行为可能存在浏览器差异，发布前按实际支持浏览器验证。
- 浏览器可能挂起后台；恢复后仍应能继续处理标签，配置不能依赖后台常驻。
- 商店的权限、隐私和签名要求不同；通过本地测试不代表已经通过商店审核。

## 14. v1.3.0 功能扩展与验收

本节描述已实现的本版需求，不代表全部完成浏览器验收。复制、分组前置修复、popup 与 Firefox 选项入口已通过阶段性 Firefox 验证；最终集成状态见 [开发计划](development-plan.md)。

### 14.1 图标 popup 与选项入口（已实现，Firefox 已验证，最终集成待回归）

- 配置 `action.default_popup`，点击图标打开面板；面板初始化后请求后台执行当前 `clickAction`，只执行一次，不再使用 `action.onClicked`。
- 后台负责同步与折叠；同步仍覆盖所有窗口，折叠限定为打开面板时的窗口。面板提前关闭不会取消已开始的后台动作。
- 面板显示执行中、完成或失败结果，文案跟随配置语言。结果显示 3 秒，再以 300ms 淡出内容并自动关闭。
- Firefox 图标右键菜单提供「选项」入口，点击打开设置页；仅 Firefox 包声明 menus 权限，菜单跟随浏览器语言。
- popup 提供「设置」入口，点击打开配置页；鼠标移到设置按钮或使用键盘时取消自动关闭，方便操作。
- 不再发送网页提示消息、不注入提示浮层；无需通知权限，不依赖当前网页的内容脚本或站点权限。保存/导入触发同步不会打开面板。
- 后续可在 popup 中加入更多操作和设置，本次保留现有 clickAction 配置，不新增模式选项。

### 14.2 分组前置（v1.3.0 已实现，Firefox 复测通过；Chrome / Edge 待验证）

- 全局配置提供「分组前置」开关，默认关闭，随配置保存与导入导出；字段 `groupsFirst` 为可选布尔值，缺省为 false。
- 开启后，每次全量同步完成（点击图标、保存、导入或控制台同步）将分组移到前面、游离标签移到后面。自动新建/归组、阈值批量归组、手动改变归属、创建时已在组内的标签及严格模式移出后，也会整理受影响窗口；同窗口同批只整理一次，并重新查询归组后的实际位置。单纯归属事件只整理位置，不重新匹配规则或干预手动分组结果。
- 所有窗口各自整理，不跨窗口移动；按浏览器当前标签顺序处理，保留分组、组内标签与游离标签各自的相对顺序。
- 使用 tabGroups.move 按原顺序将分组整体移到固定标签之后，不直接移动固定或游离标签，不改变分组归属、名称、颜色或折叠状态。已符合顺序时不操作；一个窗口移动失败时停止该窗口，继续其他窗口。原先移动游离标签的方式在 Firefox 实测中会使其并入末组，已替换；2026-11-20 Firefox 修复后复测通过，不再误入分组；Chrome / Edge 待验证。
- 验收：分组和游离标签穿插时，执行同步后分组在前、游离标签在后，各自保持原顺序；再次同步不重复移动。

### 14.3 复制规则（v1.3.0 已实现，Firefox 测试通过；Chrome / Edge 待验证）

在分组上提供「复制」，复用页面内标识、标题规则、阈值、匹配地址等配置；颜色按副本的新序号计算，便于小幅修改相似环境地址。

- 分组 ⋯ 菜单提供「复制」，副本追加到列表末尾并自动选中。
- 深拷贝样式、标题规则、阈值、备注及匹配路径等配置，颜色沿用新建规则按序号循环取色的逻辑，生成新 id 和唯一名称；名称在创建时按界面语言生成副本后缀，之后不随语言切换改写。
- 副本默认停用，匹配路径原样复制；提示用户按需修改路径并启用后保存。
- 复制只修改配置页草稿，不自动保存或执行分组。

### 14.4 追加导入（v1.3.0 已实现，待浏览器验证）

- 配置管理保留「导入 JSON…」（整份替换），增加「追加导入…」。只读取文件的 rules，忽略所有全局设置（即使全局字段取值不合法），仍检查 schemaVersion 与规则字段是否合法。
- 文件内规则按原顺序追加到当前规则末尾，保留匹配路径、样式、标题规则、备注、启用状态等；当前全局设置保持不变。
- 分组名与已有或本次已追加的规则同名时改为「原名-导入」；仍冲突则使用「原名-导入-2」「原名-导入-3」等。id 冲突时生成唯一新 id。
- 校验合并结果后询问确认，提示会保存当前配置并忽略文件全局设置；取消或非法文件不改变配置。确认后保存并同步，选中首个追加分组。页面现有未保存修改会随当前配置一起保存。
- 空规则文件不写入配置。保存失败时不替换页面草稿；已保存但同步失败时提示可重试同步。

### 14.5 从当前窗口分组创建规则（v1.3.0 已实现，待浏览器验证）

- 分组列表新增按钮改为「＋ ▾」菜单，提供「新建空白规则」「从当前窗口分组创建规则」；不加入图标行为选项。
- 在设置页读取当前窗口原生分组及标签，仅为没有同名现有规则的分组生成草稿，追加到现有列表末尾并选中首条新增项；停用规则也算已有规则，不重复生成。
- 一个命名分组生成一条规则，保留名称、颜色、折叠状态，默认 enabled=true、minTabs=1，页面标识与标题规则缺省关闭；按分组标签在窗口中的顺序生成，多个同名原生组合并成一条规则。
- patterns 默认取每个 HTTP/HTTPS 页面的 origin + `/*`（协议、域名与非默认端口）；去重并移除账号、路径、查询、片段。跳过固定/游离标签、非 HTTP(S) 页面、未命名组和没有可用网站的组，不跨窗口读取。
- 不改动浏览器分组或其他现有草稿，不自动保存/同步；提示保存后生效，可用放弃修改撤销。重复执行会跳过已生成草稿中的同名分组。
- 新增菜单支持点击空白处、Escape 收起，键盘上下方向键选择；原空白规则创建流程保留。

### 14.6 手动拖入分组后添加匹配路径（v1.3.0 已实现，待实测）

- 监听标签 groupId 变化。仅当目标组标题能唯一对应已有 TabPilot 规则、URL 为 HTTP(S)、规则尚未覆盖 URL 时生成待确认项；无对应规则的原生手动分组静默，不创建规则。
- 本插件动作层发起的自动归组加内部标记，不触发询问。浏览器事件不提供“拖动来源”，其他插件发起的归组也可能被视为外部归组。
- popup 文案为「是否将该网站加入〈分组名〉的匹配规则？」；输入框默认取当前 URL 的 origin + `/*`，保留协议、主机和非默认端口，去掉账号、路径、查询与片段。用户可修改输入。
- 提供「加入分组」和「取消」。确认时复用 expandPattern 扩写，校验地址、去重，仅追加到对应现有规则，不改变规则启用状态或顺序；保存后同步。取消不改配置、不移出标签。
- 确认表单不自动关闭，不触发默认点击同步。待确认项独立保存在本机，按窗口排队，每个标签保留最新项，总计最多 50 项；打开表单和保存前复查标签、分组、站点及目标规则，失效时拒绝写入。
- 支持后台自动打开时调用 action.openPopup；Firefox 149 以下、Chromium 127 以下或打开失败时，用角标提示用户点击图标处理。不提升项目最低浏览器版本。
- 保存成功后显示结果 3 秒再淡出关闭；无效输入或保存失败时保留表单与输入，允许修正或取消。

### 14.7 分组规则拖拽排序（v1.3.0 已实现，待浏览器验证）

- 左栏分组条目可直接拖拽，目标行上半部表示插入前方，下半部表示插入后方，显示插入线与拖动状态。
- 放下后仅更新配置页草稿中的 rules 顺序，保持当前选中项、规则内容和其他未保存修改；点击「保存并同步」后生效，可用「放弃修改」撤销。
- 全局配置固定置顶、不参与拖拽；外部文件/文字、分组操作按钮和忙碌状态不能触发排序；取消拖动或放回原位置不改变配置。
- 保留 ⋯ 菜单的上移/下移入口，便于键盘操作。无额外权限或依赖。

### 14.8 全局配置卡片与严格模式

- 语言、图标行为、自动更新分组规则、操作结果提示、分组前置共五张等尺寸卡片，两列排列；名称、控件和描述位于同一卡片内。
- 三个全局功能开关使用拨杆，严格模式拨杆放在各组的基础配置中，默认关闭、分别生效。「自动折叠」与「严格模式」采用和全局一致的两列卡片，分别展示名称、开关及描述。默认值、保存与兼容规则见 §5；不再提供 globalEnabled 全局启停，也不显示左栏全局启停状态。
- 严格模式按已启用规则的完整 patterns 判断导航后网址，协议、域名、端口和路径均参与，组数量阈值不影响归属判断；固定标签、纯手动组、歧义重名组及内部页不处理。
- 移出前重新读取标签实际归属，过期事件跳过；本批移出后不再立即归组，后续事件仍可按其他规则处理；保存配置时的全量同步不清理已有组。
