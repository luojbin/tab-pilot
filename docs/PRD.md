| 项         | 内容                                                         |
| ---------- | ------------------------------------------------------------ |
| 版本       | v0.1.0（草案）                                               |

| 目标浏览器 | Firefox 139+（仅此，多浏览器为后续计划）                     |

------

## 1. 背景与问题

当前通过多个独立浏览器插件分别实现“标签页分组、高亮、重命名”等能力，存在：

1. **零碎**：规则散落在多个插件，行为不一致，难以统一调整。
2. **不可控**：无法集中定义“什么 URL 进什么组、什么颜色”。
3. **不可迁移**：配置无法备份/恢复，换机器成本高。
4. **权限冗余**：多个插件叠加申请权限，隐私面扩大。

目标：用一个自制 Firefox 插件，以**统一规则引擎**收编 80% 高频场景，其余低频操作保留手动。

## 2. 目标与非目标

### 2.1 目标（v1.0.0 验收）

- 用 JSON 规则定义“URL 匹配 → 分组/颜色/折叠”。
- 规则可启用/禁用、有优先级、支持导入导出。
- 有操作日志，能排查“哪个 tab 命中哪条规则、做了什么”。
- 连续使用一周，可卸载至少一个现有旧插件。

### 2.2 非目标（本阶段明确不做）

- 多浏览器（Chrome/Edge/Safari）兼容。
- 复杂图形化规则编辑器（第一版用 JSON textarea）。
- 云同步、账号体系。
- 标签页重命名作为**实验功能**，不阻塞 v1.0.0。
- 机器学习/智能推荐规则。
- 任何形式的数据上传。

## 3. 用户与场景

**唯一目标用户**：你自己（后端开发者，Firefox 主力，日常多环境切换）。

核心场景：

| #    | 场景                        | 期望行为                   |
| ---- | --------------------------- | -------------------------- |
| S1   | 打开 `localhost:*` 调试服务 | 自动进入“开发”组，绿色     |
| S2   | 打开 GitHub / GitLab        | 自动进入“代码”组，蓝色     |
| S3   | 打开 Jira / Confluence      | 自动进入“工作”组，橙色     |
| S4   | 同域名标签过多              | 可选：同一窗口内命中同一条规则的标签数达到该规则自定义阈值（`match.minTabs`）时自动归组 |
| S5   | 临时不想被自动分组          | 可禁用单条规则或全局暂停   |
| S6   | 换机器                      | 导出 JSON 配置，新机器导入 |

## 4. 功能需求

### F1 规则引擎自动分组（P0，核心）

- 监听 `tabs.onCreated`、`tabs.onUpdated`（仅 `status === "complete"` 或 URL 变化时触发）。
- 按规则在配置中的顺序（即优先级）匹配 URL；命中后执行动作。
- 阈值：每条规则可自定义 `minTabs`（默认 `1`，即命中即归组）。设为 N 时，只有同一窗口内命中该规则的标签页数量 ≥ N 才归组；未达阈值的规则不生效，继续尝试后续规则。达成阈值时，同窗口内命中该规则且尚未归入任何分组的标签页一并归组，已在其他分组内的标签保持不动。
- 幂等：已处于目标组/颜色则不重复操作。
- 全量同步：事件监听覆盖不到已打开的标签页，因此提供「同步」动作——保存配置后自动执行，也可由工具栏按钮或控制台手动触发。默认跳过已在分组内的标签，避免覆盖手动整理结果。
- 防循环：用 `handled` 标记或状态比较，避免分组引发 `onUpdated` 死循环。
- 批量/防抖：短时间多个 tab 事件合并处理。

**验收**：打开 3 个 `localhost` 页面，自动进入同一“开发”组、绿色，日志各打印一条命中记录。

### F2 分组属性设置（P0）

- 支持设置分组：名称、颜色（Firefox 预设色）、是否折叠。
- 折叠在 Firefox 上按原生行为处理；跨浏览器折叠差异不在本版范围。

**验收**：规则中改颜色后，新命中 tab 使用新颜色；已有组按规则更新。

### F3 规则管理（P1）

- 规则字段：`id`、`enabled`、`name`、`color`、`collapsed`、`minTabs`、`note`、`patterns[]`。
- 支持启用/禁用单条规则；支持全局暂停开关。
- 冲突处理：规则按数组顺序匹配，靠前的优先；默认一个 tab 只应用一个分组规则。
- 阈值按规则独立配置，不同规则组互不影响。
- 配置界面为两栏布局：左栏分组列表只做展示与选中（色块、名称、iOS 风格拨杆表示启用状态、⋯ 菜单内排序与删除），左栏不提供编辑入口；右栏第一行是分组名/颜色/阈值/启用/命中后折叠（后两项为拨杆开关），第二行是备注（可拖动缩放的文本域），再往下是多条匹配路径；并为后续的标签页重命名 / 页面内高亮预留位置。不使用裸 JSON 编辑（JSON 导入导出属 F4）。
- 匹配路径自动补全：输入简写即可，离开输入框或保存时展开为完整模式——不带协议补 `*://`；只写主机且无路径时同时生成「任意端口」与「无端口」两条（如 `192.168.3.213` → `*://192.168.3.213:*/*`、`*://192.168.3.213/*`）；已写端口则不展开端口变体；结尾自动补 `/*`。

**验收**：禁用某规则后，新 tab 不再命中；重新启用恢复。

### F4 配置导入/导出（P1）

- 导出为 JSON 文件（含 `schemaVersion`），文件名带日期；入口与其他全局按钮一起放在工具栏。
- 导出内容为页面当前编辑状态（含尚未保存的修改）。
- 导入时校验 schema 版本与字段合法性，非法则拒绝并逐条提示，不改动现有配置；旧格式（v1）自动迁移。
- 导入确认后替换当前配置，立即保存并同步已打开的标签页。
- 支持“恢复默认”。

**验收**：导出 → 清空 → 导入，规则与行为完全恢复。

### F5 操作日志（开发期辅助，不做独立页面）

- 记录：时间、tab URL、命中规则 id、执行动作、结果/错误。
- 结论：日志的主要使用者是开发者本人，交付给用户价值很低。因此**不做独立日志页**，保持控制台输出即可。
- `explain()` 输出的 steps（哪条规则没命中、数量差多少）继续打印到控制台，作为排查「为什么没进组」的手段。
- 日志仅本地、不上传；内存环形缓冲保留供调试。

### F6 标签页重命名（P2，实验）

- 明确标注实验性：通过 content script 修改 `document.title`，页面刷新/导航后可能丢失。
- 第一版优先做“分组重命名 + 规则备注”，标签页重命名延后。
- 若实现，失败要静默降级并记日志，不影响 F1。

## 5. 数据模型

`schemaVersion: 2`。一条规则对应一个标签页分组，`patterns` 可包含多个匹配路径，数组顺序即优先级。

```json
{
  "schemaVersion": 2,
  "globalEnabled": true,
  "rules": [
    {
      "id": "dev-localhost",
      "enabled": true,
      "name": "开发",
      "color": "green",
      "collapsed": false,
      "minTabs": 1,
      "note": "本地开发环境",
      "patterns": ["*://localhost:*/*"]
    },
    {
      "id": "code-github",
      "enabled": true,
      "name": "代码",
      "color": "blue",
      "collapsed": false,
      "minTabs": 3,
      "note": "代码托管：攒够 3 个再归组",
      "patterns": ["*://*.github.com/*", "*://gitlab.com/*"]
    }
  ]
}
```

- 存储键：`tabpilot:config`（配置）、`tabpilot:logs`（日志，可单独或 IndexedDB）。
- 所有读取经存储封装层，不散落直接调用 `browser.storage.local`。
- **分组阈值 `minTabs`**：整数，默认 `1`。值 N 表示同一窗口内命中该规则的标签页数量达到 N 时才执行归组。该字段属于规则自身，不同规则组各自定义、互不影响。
- **优先级**：不再用显式字段，规则在 `rules` 数组中的顺序就是匹配顺序，靠前的优先；配置页用上移/下移调整。
- **匹配路径**：`patterns` 数组，任一命中即视为该规则的 URL 命中。
- **旧配置迁移**：`schemaVersion: 1`（`match.urlPattern` + `actions[]` + `priority`）在读取时自动迁移为 v2 并写回，迁移不丢失规则。
- `schemaVersion` 与插件版本号解耦，仅随配置结构的不兼容变更递增。

## 6. 非功能需求

| 类别   | 要求                                                         |
| ------ | ------------------------------------------------------------ |
| 性能   | 单次 tab 事件处理 < 50ms；批量合并；不影响页面加载           |
| 可靠性 | 幂等 + 防循环；单条规则异常不影响其他规则                    |
| 隐私   | 无网络请求上传数据；权限最小化                               |
| 权限   | 首版仅 `tabs`、`tabGroups`、`storage`；如需要 `unlimitedStorage` 再申请 |
| 可测试 | 规则引擎为纯函数，可脱离浏览器单测                           |
| 可维护 | 规则引擎 / 动作执行 / 存储 三层分离                          |

## 7. 技术架构（概要）

```
background.js      事件监听 + 调度
  ├─ rules.js      纯函数：match(tab, rules) → actions[]
  ├─ actions.js    执行 browser.tabs.group / tabGroups.update
  ├─ store.js      封装 storage.local 读写 + schema 校验
  └─ logger.js     写日志、读日志
options.html/js    两栏配置页：左栏分组列表（只读、选中、排序/删除），右栏分组详情（分组名/颜色/阈值/启用/折叠/备注/匹配路径，并预留标签重命名、页面高亮）；工具栏含保存/放弃/恢复默认与导入/导出
manifest.json      MV3，background.scripts（非 service worker）
```

**为未来多浏览器预留的薄缝**（本版不实现兼容层）：

1. 规则引擎与 `browser.*` API 解耦（只依赖 actions 层）。
2. 存储封装层（以后换 IndexedDB/同步只改此层）。
3. 配置带 `schemaVersion`，便于迁移。
